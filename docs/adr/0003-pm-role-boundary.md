# ADR 0003: PM 역할 경계 명확화

- 상태: 승인됨
- 날짜: 2025-09-02
- 작성자: PM Claude

## 배경(문제/문맥)
- Issue #82 작업 중 PM이 AI Adapter 코드를 직접 작성
- "이 작업은 실제로 누가 한거야?"라는 사용자 질문
- PM 역할과 AI 역할의 경계 모호함 발견

## 결정(Decision)
### PM의 역할 (해야 할 것)
1. **분석과 판단**: 요구사항 분석, 작업 분류
2. **이슈 생성**: GitHub 이슈 생성 및 관리
3. **방향 제시**: 참조 파일, 패턴, 가이드라인 제공
4. **품질 검증**: 결과물 검토 및 피드백

### PM의 금지사항 (하면 안 되는 것)
1. **코드 작성 금지**: 어떤 형태의 구현 코드도 작성 불가
2. **직접 구현 금지**: 파일 생성, 수정, 삭제 직접 수행 불가
3. **샘플 제공 금지**: "이렇게 하세요"라며 코드 제시 불가

## 근거(Why)
- **역할 명확성**: PM은 관리자, AI는 실행자
- **확장성**: PM 1명이 여러 AI 관리 가능
- **자율성**: AI의 학습과 성장 기회 보장
- **책임성**: 누가 무엇을 했는지 명확히 추적

## 대안(Alternatives)
1. ❌ PM이 필요시 코드 작성 → 역할 혼재, 확장성 저하
2. ❌ AI만 작업 → 방향성 부재, 품질 불일치
3. ✅ 명확한 역할 분리 → 효율적 협업

## 결과(Consequences)
### 긍정적
- 역할 책임 명확화
- AI 자율성 증대
- 시스템 확장성 향상

### 부정적
- 초기 AI 학습 곡선
- 에스컬레이션 프로세스 필요

## 실행 지침

### ✅ 올바른 PM 행동
```
PM: "storage_adapter를 구현해주세요. 
     참고: ai_orchestration_adapter.py
     요구사항: 파일 저장/조회 기능"
```

### ❌ 잘못된 PM 행동
```
PM: "이렇게 구현하세요:
     class StorageAdapter:
         def save(): ..."
```
